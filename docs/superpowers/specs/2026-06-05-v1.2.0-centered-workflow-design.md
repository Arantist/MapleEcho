# MapleEcho v1.2.0 Centered Workflow Design

## Goal

将 MapleEcho 主界面从左右两列改成居中的单列处理流程，并在分离完成后通过横向滑动动画切换到独立的结果与练习工作台。保持现有品牌、后端 API、上传流程和任务轮询逻辑不变。

## Page Structure

页面使用两个互斥视图：

1. `setup`：上传、目标轨道、处理模式、开始分离和状态。
2. `results`：分离结果、播放器、下载操作和练习模式。

固定顶栏在两个视图中保持可见。页面主体使用约 `860px` 的最大宽度居中显示，桌面和移动端均使用单列流程。

## Setup View

主界面按照以下顺序展示：

1. 上传音频卡片。
2. 目标轨道选择卡片。
3. 处理模式选择卡片。
4. 开始分离按钮和轻量状态区。

上传、轨道和模式卡片继续使用现有交互与文案。处理期间停留在主界面，状态区持续显示上传、排队、后端处理和进度信息。分离失败时留在主界面展示错误，方便用户直接重试。

## Results View

任务完成并生成两个结果 URL 后，页面自动切换到结果视图。结果工作台按照以下顺序展示：

1. 顶部操作栏：完成状态、当前目标轨道、返回设置按钮。
2. 目标轨道结果卡片：播放器和下载按钮。
3. 去目标伴奏结果卡片：播放器和下载按钮。
4. 练习模式卡片：AB Loop、变速、变调占位交互。

返回设置时保留已选择文件、目标轨道、处理模式和已完成结果。用户可以修改设置并再次开始分离；新任务开始后继续停留在主界面，完成后再次切换到结果视图。

## View Transition

视图状态使用本地 React state 管理，取值为 `setup` 或 `results`。

完成任务时：

- `setup` 视图向左轻微位移并淡出。
- `results` 视图从右侧进入并淡入。
- 动画时长约 `450ms`，使用 CSS transition 和 keyframes，不引入动画依赖。

返回设置时使用反向动画：

- `results` 向右轻微位移并淡出。
- `setup` 从左侧进入并淡入。

动画期间保持稳定的页面宽度，禁止横向滚动。尊重 `prefers-reduced-motion`，用户关闭动态效果时直接切换视图。

## State And Data Flow

保留现有状态和 API 流程：

- `selectedFile`
- `selectedTarget`
- `selectedMode`
- `isProcessing`
- `statusText`
- `job`
- `result`

新增：

- `activeView: "setup" | "results"`
- `transitionDirection: "forward" | "back"`

创建任务、轮询任务和构建结果数据的逻辑保持不变。只有当任务状态为 `completed` 且 `result` 成功构建后，才自动进入结果视图。失败和缺少结果 URL 时不跳转。

## Responsive Behavior

桌面端主流程和结果工作台均居中，最大宽度约 `860px`。目标轨道和模式选择继续在空间足够时使用两列卡片。

移动端维持单列页面，轨道和模式卡片在窄屏下改为单列。视图切换动画减少位移距离，顶栏右侧轻量文案继续隐藏。

## Scope

本次修改聚焦 `app/page.tsx` 的布局和交互，并更新项目版本为 `1.2.0`。如样式需要复用，可少量修改 `app/globals.css`。不修改 `app/layout.tsx` 的品牌元数据，不修改 FastAPI 后端接口，不实现 AB Loop、变速和变调的音频处理功能。

## Verification

完成后验证：

- 初始页面只显示居中的主处理流程，不显示结果和练习卡片。
- 未上传文件时开始按钮禁用。
- 处理中停留在主界面并显示进度。
- 分离完成后自动正向动画切换到结果工作台。
- 返回设置触发反向动画并保留当前选择。
- 错误状态不会跳转到结果视图。
- 桌面和移动端无横向溢出或内容重叠。
- `npm run lint`、`npm test` 和 `npm run build` 通过。
